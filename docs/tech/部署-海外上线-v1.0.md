## §1 数据库（托管 PostgreSQL）

1. 创建实例（pg 16），记录连接串：`postgresql://<user>:<pass>@<host>:5432/<db>?schema=public`（Neon 等要求 `?sslmode=require`，按其控制台给出的串为准）。
2. 应用迁移（在仓库 `eatwise_server/` 下，行内传 DATABASE_URL，**不要写进任何会被提交的文件**）：
   ```bash
   cd eatwise_server
   DATABASE_URL='<生产连接串>' npx prisma migrate deploy
   ```
3. 灌食物库（7455 条，幂等可重跑）：
   ```bash
   DATABASE_URL='<生产连接串>' npm run prisma:seed
   ```
4. 备份策略：确认托管方自动快照已开启（Neon/Render 默认有 PITR 或每日快照）；上线后 **每月做一次恢复演练**（恢复到临时实例 → `prisma migrate deploy` 验证 → 抽查 users/food_entries 行数）。
5. 连接池：托管 pg 若经 PgBouncer（Neon/Supabase 默认），DATABASE_URL 加 `?pgbouncer=true&connection_limit=1`（Prisma 官方口径）。

## §2 服务端部署（以 Render 为例）

### 2.1 创建 Web Service
- 仓库：`github.com/chunguangwei/EatWise`（私有，授权 Render 读取）
- Root Directory：`eatwise_server`
- Build Command：`npm ci && npx prisma generate && npm run build`
- Start Command：`node dist/main.js`
- Health Check Path：`/v1/health`

### 2.2 环境变量（Render Dashboard → Environment）

| 变量 | 值 | 必需 |
|------|-----|------|
| `PORT` | `3000`（Render 自动注入时可省） | ✅ |
| `STORE_DRIVER` | `prisma` | ✅ |
| `DATABASE_URL` | §1 连接串 | ✅ |
| `JWT_SECRET` | `openssl rand -base64 48` | ✅ |
| `JWT_ACCESS_TTL_SEC` | `7200` | ✅ |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 管理员种子（启动自动建号，建后可改密） | ✅ |
| `ADMIN_JWT_SECRET` | 独立强随机（缺省由 JWT_SECRET 派生，生产必须显式配） | ✅ |
| `ADMIN_TOKEN` | **留空**——过渡兜底 `x-admin-token` 上线必须下线（视为 admin 后门） | ⛔ 禁配 |
| `REDIS_URL` | 托管 Redis 串（不配则限流/热配置退化内存，单实例可接受） | 可选 |
| `FASTING_TOLERANCE_MINUTES` | `15`（D-08，热调） | 可选 |
| `GITHUB_RELEASE_TOKEN` | repo 只读 PAT（App 内更新检查代理私有仓 Releases） | ✅ |
| `APP_LATEST_VERSION` / `APP_MIN_SUPPORTED_VERSION` | 发版后同步（如 `1.1.0` / `1.0.0`） | ✅ |
| `LLM_PROVIDER` / `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 服务端 AI 估算兜底（stub 则返回 ESTIMATE_UNAVAILABLE，客户端降级） | 可选 |
| `ADMIN_CONFIG_PATH` | 缺省 `data/admin-config.json`；Render 临时盘重启即失，**LLM 运行时覆盖配置在重建后丢失**——需要持久则挂 Disk 或只用 env | 可选 |

### 2.3 首次部署后验证
```bash
curl https://api.<你的域名>/v1/health
# → {"data":{"status":"ok"},...}
```

### 2.4 通用部署路径（非 Render 时）
任意支持 Node 20+ 的平台/裸机：
```bash
npm ci && npx prisma generate && npm run build
DATABASE_URL=... STORE_DRIVER=prisma JWT_SECRET=... node dist/main.js
```
- 裸机用 pm2/systemd 守护 + Caddy/Nginx 反代出 HTTPS。
- **多实例注意**：上传图片默认落本地盘（`STORAGE_DRIVER=local`）且限流/smsCodes 在内存——上线初期单实例运行；`STORAGE_DRIVER=s3`（§3）+ Redis 后才可水平扩展。

## §3 对象存储（打卡图片，local / s3 双驱动已实现）

现状（2026-09-14 迁移完成）：存储驱动抽象已落地，`STORAGE_DRIVER=local|s3` env 切换（模式与 STORE_DRIVER 一致，见 `src/uploads/uploads.storage.ts` 的 `UploadsStorage` 接口与 `uploads.module.ts` 工厂）：

- **local（默认）**：`POST /v1/uploads` 落服务本地盘（魔数嗅探 jpg/png/webp ≤5MB），`GET /v1/uploads/:filename` sendFile 直出。仅单实例可用，多实例/重建即丢。
- **s3（上线形态）**：`S3UploadsStorage`（`src/uploads/s3-uploads.storage.ts`，@aws-sdk/client-s3）PUT 到 R2/S3 桶，公开读走 CDN——上传返回 `url = ${CDN_BASE_URL}/${id}`；`GET /v1/uploads/:filename` 302 重定向到同一 CDN 地址（端点契约不变，老客户端与 Image.network 公开读无感）。必需 env 缺失时启动即 fail fast。

上线操作清单：
1. 建桶与 CDN：Cloudflare R2（或 AWS S3）+ 公开读域名（R2 自定义域 / CloudFront）。
2. 配置 env（缺一启动即报错）：`STORAGE_DRIVER=s3`、`S3_BUCKET`、`S3_ACCESS_KEY`、`S3_SECRET`、`CDN_BASE_URL`；R2 另需 `S3_ENDPOINT=https://<account_id>.r2.cloudflarestorage.com`（`S3_REGION` 缺省 `auto`；AWS S3 填实际区域、`S3_ENDPOINT` 留空）。模板见 `eatwise_server/.env.example`「图片上传存储」节。
3. 存量本地文件一次性搬运（上线前无存量则跳过）：`uploads/` 内文件按原名 PUT 到桶根即可（Key=文件名，与代码拼接规则一致）。
4. 图片先审后发链路与 §4.2 内容审核串接（上传 → 审核通过 → 帖子可见）。

## §5 App 发版

### 5.1 指向生产 API
- GitHub 仓库 → Settings → Secrets and variables → Actions → Variables：`API_BASE_URL=https://api.<你的域名>/v1`（**必须带 /v1**，踩坑 4）。
- 本地/真机联调：`flutter run --dart-define=API_BASE_URL=https://api.<你的域名>/v1`。

### 5.2 Android release 签名（当前 debug，阻塞正式分发）
```bash
keytool -genkey -v -keystore eatwise-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias eatwise
```
- CI secrets 配置：`KEYSTORE_BASE64`（`base64 -i eatwise-release.jks`）/ `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`（release.yml:44 TODO 处），构建改 `--release`。
- keystore 文件离线备份两份，**丢了等于失去更新权**。

### 5.3 iOS 上架
1. Xcode → Signing：确认 Team（`L35RLT89XN` 或新账号）+ 自动签名。
2. ATS：生产 API 必须 HTTPS（部署后自然满足）；局域网 http 放行（`NSAllowsLocalNetworking`）仅用于 LLM 直连，保留。
3. App Store Connect：新建 App → 填 Apple App Privacy 标签（健康数据口径逐条对齐 §D-18 v2）→ 隐私政策 URL（§0.10）→ 年龄分级（健康类建议 12+〔假设〕）→ 截图与描述（中英）。
4. 若保留第三方登录（微信等），必须同时提供 Sign in with Apple（Apple 5.1.1）；纯账号密码不强制。
5. 提审：`flutter build ipa` → Transporter 上传 → TestFlight 灰度 → 提审。

### 5.4 发版流水线（已就绪）
`git tag v1.x.x && git push origin v1.x.x` → release.yml 自动构建 APK + GitHub Release；服务端 `GITHUB_RELEASE_TOKEN` 代理更新检查。

## §7 运维与回滚

- **迁移**：schema 变更 = 新迁移目录 + `prisma migrate deploy`（部署流水线内置此步）；禁止 `migrate dev` 对生产。
- **回滚**：代码回滚 = Render 重新部署旧 commit；**数据库不回滚**（迁移只前滚，破坏性变更拆两步：先兼容后清理）。
- **监控**：托管平台自带 uptime 告警 + `/v1/health` 外部拨测（如 UptimeRobot）；Crashlytics 告警邮箱。
- **日志**：当前 console 输出（Render 面板可查）；后续按需接结构化日志。
- **GDPR 例行**：删除请求走 App 内 U5（7 天冷静期自动硬删）；导出 U3 已实现，无需人工。
