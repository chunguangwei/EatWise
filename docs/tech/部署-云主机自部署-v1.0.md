# 《EatWise 云主机自部署手册》v1.0

> 场景：你有一台云主机（VPS），要把服务端完整跑在自己机器上——PostgreSQL + NestJS + HTTPS 一站式。
> 与 `部署-海外上线-v1.0.md`（Render 托管路线）是**二选一**关系；本文自给自足，全部命令可直接照抄。
> 涉及文件（均已入库）：`eatwise_server/Dockerfile`、`docker-compose.prod.yml`、`deploy/Caddyfile`、`deploy/certs/cert.pem`、`deploy/env.prod.example`。
> 端口方案：Caddy 只监听 **8443**，**不占用 80/443**；证书为**自签名（50 年期）+ 客户端证书锁定（pinning）**，不依赖任何 CA 与 DNS API。

---

## §0 前置条件（一次到位）

| 项 | 要求 | 说明 |
|----|------|------|
| 云主机 | ≥1C2G，40G 盘，Ubuntu 22.04/24.04（示例命令按 apt 系） | 2G 是 Docker 构建的底线，构建时内存不足可先 `npm run build` 在外机做或加 swap |
| 域名 | `wcg.polin.tech` 的 A 记录指向主机 IP | 自签名方案下域名只用于连接寻址与 SAN 匹配，不需要 DNS API 凭证 |
| 安全组/防火墙 | 只放行 22 / 8443 | **80/443 不用开**（方案不占这两个端口）；**5432、3000 绝不对外**（compose 内网通信，无宿主机映射） |
| Docker | Docker Engine 24+ 与 compose 插件 | 下方有一键安装命令 |

```bash
# Ubuntu 一键装 Docker（官方源）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # 重新登录后免 sudo
docker compose version           # 验证 compose 插件在场
```

## §0.5 证书说明（自签名 + pinning）

- 证书已预生成：`deploy/certs/cert.pem`（公钥，**已提交 git**）+ `deploy/certs/key.pem`（私钥，**禁止入库**，已 gitignore）。
- 参数：50 年有效（18250 天，2026-09-18 签发，至 **2076-09-05**），SAN = `DNS:wcg.polin.tech`；SHA-256 指纹
  `7B:01:F0:23:54:D7:77:4B:CF:47:92:D0:A6:58:D7:C0:1D:F5:24:F8:7C:2B:75:E4:18:F8:1C:FB:11:22:92:FD`。
- **App 内置证书锁定（pinning）只认这张证书**——这是自签名方案的安全基石：即使私钥之外的网络路径被劫持，客户端也会拒绝其他证书。
- 浏览器访问管理控制台时会有证书警告，属预期，手动确认信任即可。
- **到期/换证纪律**：2076-09-05 前（或私钥泄露时）必须重新生成证书对，并**同步发布内置新指纹的新版 App**；旧证书一撤，旧版 App 立即连不上，灰度切换要提前规划。
- `key.pem` 不进 git，需随部署包手工上传到主机（见 §1）。

## §1 拉代码

```bash
git clone https://github.com/chunguangwei/EatWise.git   # 私有仓需配 PAT 或 deploy key
cd EatWise/eatwise_server
```

然后补上私钥（git 里没有，从本地保管处上传）：

```bash
# 在持有 key.pem 的机器上执行：
scp deploy/certs/key.pem <user>@<主机>:~/EatWise/eatwise_server/deploy/certs/key.pem
# 主机上确认权限：
chmod 600 deploy/certs/key.pem
ls -l deploy/certs/   # 应有 cert.pem（随 git 来）+ key.pem（刚传的）
```

## §2 配置（唯一需要动脑的步骤）

```bash
cp deploy/env.prod.example .env.prod
$EDITOR .env.prod
```

逐项说明（模板里也有注释）：

| 变量 | 怎么填 |
|------|--------|
| `PG_PASSWORD` | `openssl rand -base64 24` 生成 |
| `DATABASE_URL` | 只把密码段换成与 `PG_PASSWORD` 一致，主机名 `postgres` 不动（compose 内网 DNS） |
| `JWT_SECRET` / `ADMIN_JWT_SECRET` | 各 `openssl rand -base64 48`，**必须显式填**——生产缺省启动直接 fail fast（9-14 修复后行为） |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 管理员种子账号，启动自动建号 |
| `GITHUB_RELEASE_TOKEN` | repo 只读 PAT（App 内更新检查代理私有仓 Releases 用） |
| `APP_LATEST_VERSION` / `APP_MIN_SUPPORTED_VERSION` | 当前 `1.8.2` / `1.0.0`，以后每次发版同步改 |
| `STORAGE_DRIVER` | 先 `local`（落 uploads/ 卷）；迁 R2/S3 见 `部署-海外上线-v1.0.md` §3 |
| `ADMIN_TOKEN` | **不要配**（后门变量，生产必须留空） |

域名与端口已写死在 `deploy/Caddyfile`（`wcg.polin.tech:8443` + 自签名证书路径），一般不用动；换域名时需重新生成证书（SAN 要匹配）并同步 App pinning。

## §3 构建与启动

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
```

一条命令做完四件事（按 depends_on 顺序）：
1. `postgres`：起 pg16，数据落 `pgdata` 卷，不对外
2. `migrate`：一次性任务——`prisma migrate deploy` 建表 + `prisma:seed` 灌 7455 条食物库（幂等，可重跑）
3. `server`：起 NestJS（`STORE_DRIVER=prisma`），带健康检查，`./uploads`（图片）挂宿主机持久化
4. `caddy`：官方镜像加载 `deploy/certs/` 自签名证书（只读挂载），8443 反代到 server

## §4 验证（逐项过，全绿才算完）

```bash
# 4.1 四个容器状态：server/postgres/caddy = Up，migrate = Exited (0)
docker compose -f docker-compose.prod.yml ps

# 4.2 健康检查（容器内一次 + 公网一次）
# server 无宿主机端口映射（设计如此），本机直连须进容器验证：
docker compose -f docker-compose.prod.yml exec server wget -qO- http://localhost:3000/v1/health
# 公网走 8443；自签名证书 curl 需加 -k 跳过 CA 校验：
curl -k https://wcg.polin.tech:8443/v1/health
# → {"data":{"status":"ok"},...}

# 4.2.1 核对证书指纹（确认线上跑的就是 pinning 那张）
echo | openssl s_client -connect wcg.polin.tech:8443 -servername wcg.polin.tech 2>/dev/null \
  | openssl x509 -noout -fingerprint -sha256
# 应与 §0.5 的指纹一致

# 4.3 注册登录冒烟
curl -k -X POST https://wcg.polin.tech:8443/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"smoketest","password":"Test1234!"}'

# 4.4 食物搜索（种子库在库验证）
curl -k 'https://wcg.polin.tech:8443/v1/foods/search?q=rice' -H "Authorization: Bearer <token>"

# 4.5 重启存活（数据真落库验证）
docker compose -f docker-compose.prod.yml restart server
# 再登录 smoketest，数据应在
```

管理控制台：`https://wcg.polin.tech:8443/admin`，用 `ADMIN_USERNAME/PASSWORD` 登录（浏览器会提示证书不受信，手动确认继续即可，预期行为）。
完整验收清单（含同步/图片/审核链路）见 `部署-海外上线-v1.0.md` §6，照过一遍。

## §5 让 App 指向这台机器

```bash
# GitHub 仓库 → Settings → Variables → Actions（或 gh CLI）
gh variable set API_BASE_URL --body "https://wcg.polin.tech:8443/v1"   # 必须带 /v1 与 :8443
```

此后打 tag 出的 APK 全部指向生产，且内置 pinning 只认 §0.5 的证书。**已装局域网包的手机**：App 内会提示更新，用户更新即切到生产；旧包指向的老 IP 不再可用属预期。

## §6 日常运维

```bash
# 更新服务端（发新版代码）
git pull
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build
#   migrate 每次都会跑：新迁移自动 deploy，seed 幂等跳过，无需人工

# 看日志
docker compose -f docker-compose.prod.yml logs -f server

# 发版 App 后同步版本号
$EDITOR .env.prod   # APP_LATEST_VERSION=1.8.3
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d server
```

**数据库备份**（pg 是唯一有状态服务，必须备）：

```bash
# 手动备一份
docker exec eatwise-prod-postgres pg_dump -U eatwise eatwise | gzip > backup-$(date +%F).sql.gz

# 每日定时备（crontab -e，保留 14 天）
0 3 * * * cd ~/EatWise/eatwise_server && docker exec eatwise-prod-postgres pg_dump -U eatwise eatwise | gzip > backups/$(date +\%F).sql.gz && find backups -mtime +14 -delete
```

恢复演练（每月一次）：`gunzip -c backup-xxx.sql.gz | docker exec -i eatwise-prod-postgres psql -U eatwise eatwise`（建议恢复到临时实例验证，别直接盖生产）。

## §7 安全清单（上线前自查）

- [ ] `JWT_SECRET` / `ADMIN_JWT_SECRET` 是强随机且互不相同（缺省值在公开仓库，绝不能用）
- [ ] `.env.prod` 无 `ADMIN_TOKEN`
- [ ] `deploy/certs/key.pem` 权限 600、未进 git（`git status` 不应出现它），且有异地安全备份（丢了无法用同指纹换证）
- [ ] 安全组只开 22/8443；`docker compose ps` 确认 postgres/server 无宿主机端口映射
- [ ] `.env.prod` 权限 `chmod 600`，不进 git（已 gitignore）
- [ ] pg_dump 备份已跑通一次，备份文件可下载到本地异地保存
- [ ] 管理控制台能登录、`x-admin-token` 方式已失效

## §8 已知边界（单实例口径）

- **单实例运行**：smsCodes（备用验证码路径）与管理端限流在内存；多实例需先接 Redis（未做，属规划内）
- **图片 local 驱动**：多实例/换机迁移时需把 `./uploads` 一起带走；迁 R2/S3 后无此约束
- **证书**：自签名 50 年期（至 2076-09-05），无自动续期概念；换证必须与新指纹的 App 版本同步发布，属于发版纪律而非运维动作
- **换机迁移**：除 pg 备份与 uploads 外，别忘把 `deploy/certs/key.pem` 一起带走（否则只能用新证书+新发 App）
- **资源占用参考**：pg ~50MB + server ~150MB + caddy ~30MB，1C2G 富余

## §9 故障速查

| 症状 | 排查 |
|------|------|
| `migrate` 退出码非 0 | `docker compose ... logs migrate`；九成是 DATABASE_URL 密码与 PG_PASSWORD 不一致；若报 P1000 且密码确认无误，检查是否与 dev compose 共享了 pg 卷（本编排已用 `name: eatwise-prod` 隔离，勿删）；若报 `ENOENT /eatwise_data/foods.seed.json`，说明没在整仓根目录的 eatwise_server/ 下执行（seed 按 monorepo 布局挂载 ../eatwise_data） |
| server 起不来 / 反复重启 | `logs server`；production 缺 JWT_SECRET 会 fail fast（设计如此），补 env 后 `up -d` |
| caddy 起不来 / 8443 无响应 | `logs caddy`；九成是 `deploy/certs/key.pem` 没上传（git 里没有，见 §1）或权限不对；其次确认宿主机 `deploy/certs/` 下 cert.pem/key.pem 成对存在 |
| 8443 通但 curl 报证书错误 | 自签名属预期，`curl -k`；用 §4.2.1 核对指纹与 pinning 指纹一致；App 连不上先怀疑 App 内置指纹与线上证书不匹配（换过证书没发新版 App） |
| 浏览器进管理台报证书警告 | 预期行为（自签名无 CA 链），手动确认信任继续 |
| health 通但注册 500 | 看 server 日志；pg 连接问题居多，`docker compose ... exec postgres pg_isready` |
| 想回滚 | `git checkout <旧 tag> && up -d --build`；**数据库只前滚不回滚**（迁移不可逆，破坏性变更拆两步的既有纪律） |
