## 0. 名词与适用范围

- **产品**：明食 · EatWise，iOS 15+ / Android 8.0（API 26）+（D-14），Flutter 单代码库双端（D-17）。
- **MVP 上架范围**：中国大陆区（App Store 中国区 + 国内安卓应用商店）。英文界面随 MVP 提供（D-15），但**不向境外应用商店上架**，海外上架待 GDPR 评估完成后另行决策（D-15/D-18）。
- **数据分类约定**（本文档全局使用）：

| 分类 | 定义 | 本 App 涉及的数据 |
|------|------|--------------------|
| 敏感个人信息 | 一旦泄露易导致人格尊严或人身财产安全受危害的信息（PIPL §28） | 身高、体重、年龄、性别、饮食记录、断食记录（健康相关，推定属于敏感个人信息〔待外部确认：法务对口径签字〕）、手机号 |
| 一般个人信息 | 其他可识别个人的信息 | 昵称、头像、设备标识、日志 |
| 非个人信息 | 不可识别到个人的数据 | 食物库公共数据（D-16）、匿名化后的聚合统计 |

## 1. 法规适用性分析（D-18 ①）

### 1.1 中国法域（MVP 主战场，强制适用）

| 法规 | 适用点 | 对本产品的核心要求 | 落地方案章节 |
|------|--------|--------------------|--------------|
| 《个人信息保护法》（PIPL） | 全部个人信息处理活动 | 告知-同意（§13/§14）；**敏感个人信息单独同意**（§29：身高体重、饮食/断食记录等健康数据）；最小必要（§6）；可撤回同意（§15）；查阅、复制（导出）、删除权（§44–47） | §2、§4 |
| 《数据安全法》（DSL） | 数据全生命周期 | 数据分类分级保护（§21）；重要数据识别与风险评估；数据处理活动安全保护义务 | §7 |
| 《网络安全法》 | 网络运营者义务 | 网络安全等级保护（等保定级与备案〔假设：按等保二级执行，M0 启动定级备案〕）；日志留存 ≥6 个月 | §7 |
| 《移动互联网应用程序信息服务管理规定》 | App 信息服务 | 真实身份信息认证（手机号注册即满足）；App 备案（见 §8.2） | §8.2 |
| 《互联网用户账号信息管理规定》 | 账号体系 | 账号信息管理、注销入口 | §4.3 |
| 《生成式人工智能服务管理暂行办法》 | — | **不适用**：MVP 无生成式 AI 能力；一句话建议为规则模板库生成（D-05），非模型生成 | — |

### 1.2 GDPR 边界（英文版对应的评估结论）

| 问题 | 结论 | 说明 |
|------|------|------|
| MVP 是否直接适用 GDPR？ | **否（按当前边界）** | MVP 仅中国区上架（D-15），不向欧盟用户提供服务、不定向营销、不监测欧盟用户行为，不满足 GDPR §3(2) 域外适用条件 |
| 英文界面是否触发 GDPR？ | **不必然** | 英文界面服务于在华英语用户/双语用户，非「向欧盟数据主体提供商品服务」；但需在隐私政策中声明服务区域为中国大陆 |
| 偶发欧盟用户使用（如旅居用户）怎么办？ | 风险接受 + 缓释 | ① 注册时手机号限定 +86 号段为主〔假设〕；② 隐私政策明示服务区；③ 数据存储于中国境内服务器，不做跨境传输；④ 海外上架前必须完成完整 GDPR 合规评估（合法基础、DPO、SCC、DPIA），列为 V1.1+ 独立决策项（D-15） |
| 健康数据在 GDPR 下级别 | Article 9 特殊类别数据 | 若未来出海，健康数据需显式同意（explicit consent），标准高于 PIPL 单独同意——出海评估时按更高标准设计，**MVP 阶段的单独同意组件按可复用到 explicit consent 的规格实现**〔假设，降低未来改造成本〕 |

### 1.3 数据出境

- MVP **无任何数据出境**：服务器部署于中国境内，全部第三方 SDK 选用境内服务（D-17）。
- 使用的第三方服务若存在境外传输（如 FCM 不可用于国内 Android，国内走厂商通道/聚合推送，D-17），须在 SDK 清单中逐项标注并确认无境外传输（见 §6）。

**强制规则**：
- 上表即《隐私政策》附件「个人信息收集清单」的内容源，两文档逐项一致，差异即缺陷。
- 新增任何数据项须走「合规变更评审」（§9 checklist 第 12 项），更新本表与隐私政策后方可开发。
- **健康平台数据不出端**（2026-09-17，D-19 翻案边界）：HealthKit / Health Connect 数据只在本机读取与展示，服务端不落任何对应字段，不向任何第三方 SDK 提供；后续若需上云须重新走单独同意与合规变更评审。

### 3.3 权限管理硬性规则

- 任一权限被拒绝 ≥2 次后，不再主动弹系统申请，仅在对应入口保留「去设置开启」静态入口。
- 设置内提供「系统权限管理」页：列出全部权限当前状态 + 跳转系统设置的入口（中英双语说明每个权限用途）。
- 权限用途文案（系统弹窗的 UsageDescription / App 内预说明）统一走 i18n key（D-15），禁止硬编码，文案库随本文档附件维护。

## 4. 用户权利落地（D-18 ④）

### 4.1 首次启动隐私弹窗（单独同意）

| 要素 | 规格 |
|------|------|
| 触发时机 | 首次启动，**在任何数据上报/第三方 SDK 初始化之前**展示；同意前 SDK 一律延迟初始化（见 §6 强制规则） |
| 结构 | 两层：① 隐私政策摘要弹窗（《隐私政策》《用户协议》链接，概括收集范围与用途，中英双语跟随系统语言 D-15）→ ② **健康数据单独同意**独立勾选项（PIPL §29），与主同意**分离展示、分离勾选**，不得默认勾选、不得捆绑 |
| 健康数据单独同意文案要点 | 明示：收集的身高/体重/年龄/性别/饮食/断食记录属敏感个人信息；处理目的（营养目标计算与反馈）；存储位置（境内加密存储）；可拒绝及拒绝后果（营养目标用默认值兜底）；可随时在设置中撤回 |
| 拒绝路径 | 拒绝主隐私政策 → 退出 App（无法提供服务）；**仅拒绝健康数据单独同意 → 可继续使用**：账号功能正常，营养目标走默认值兜底（D-04），饮食/断食记录仅本地存储不上云〔假设：纯本地模式，待技术评估同步层开关〕 |
| 记录存证 | 同意/拒绝行为连同时间戳、版本号、政策版本号存服务端（同意日志），保留 ≥3 年〔假设〕，用于合规举证 |
| 政策更新 | 隐私政策重大变更 → 重新弹窗征得同意（含健康数据重新单独同意），历史同意日志保留 |

### 4.2 数据导出（查阅复制权，PIPL §44/§45）

| 要素 | 规格 |
|------|------|
| 入口 | 我的 → 设置 → 隐私 → 「导出我的数据」 |

### 4.3 删除账号（删除权，PIPL §47）

| 要素 | 规格 |

| 入口 | 我的 → 设置 → 账号与安全 → 「注销账号」；入口常驻，不得隐藏 |

| 第三方连带 | 通知第三方 SDK 侧删除对应用户数据（推送 token、内容审核留存的图片），并留存删除凭证 |

## 7. 数据安全（D-18 ⑦）

### 7.1 传输安全

| 项 | 规格 |
|----|------|
| 传输加密 | 全链路 **TLS 1.2+**（强制 HTTPS，禁用 HTTP 明文回退）；服务端 HSTS |
| 证书校验 | 客户端启用证书锁定（SSL Pinning）〔假设，权衡：证书轮换需灰度方案，M0 技术评审确认〕 |
| 接口鉴权 | 登录 token + 请求签名防篡改；token 过期刷新机制 |

### 7.2 服务端存储加密（敏感字段级）

| 字段 | 加密方式 |
|------|----------|
| 手机号 | AES-256-GCM 字段级加密存储；展示统一脱敏 `138****1234`；检索用不可逆 HMAC 索引 |
| 身高/体重/年龄/性别、饮食记录、断食记录 | 字段级 AES-256 加密（列加密），密钥由 KMS 管理，密钥与数据分库存放；DBA 不可直读明文 |
| 密码类 | MVP 无密码（验证码/三方登录，D-13），验证码本身 5 分钟过期 + 错误次数限流〔假设〕 |
| 备份 | 备份文件加密存储，恢复演练每季度一次〔假设〕 |

### 7.3 本地库加密（双端）

| 端 | 规格 |
|----|------|
| 方案 | SQLite（drift，D-17）启用 **SQLCipher** 全库加密；密钥派生后存入系统安全区：iOS Keychain（`kSecAttrAccessibleAfterFirstUnlock`）/ Android Keystore |
| 覆盖范围 | 本地缓存的饮食/断食记录、基础资料、待同步队列（D-20 四态数据）全部在加密库内 |
| 兜底 | 注销账号时删除密钥并销毁数据库文件（§4.3）；卸载即清除（系统行为） |

### 7.4 日志脱敏

| 规则 | 说明 |
|------|------|
| 手机号 | 日志中一律掩码（保留前 3 后 4），禁止明文 |
| 健康数据 | 饮食内容、体重数值**不进业务日志**；埋点事件只记录事件类型与计数，不记录内容 |
| UID | 日志用内部 UID，不直传手机号/设备号明文 |
| 客户端日志 | 本机调试日志 release 包关闭敏感输出；上报崩溃堆栈过滤请求体与响应体中的数据字段 |
| 留存 | 服务端访问与操作日志留存 ≥6 个月（网安法），到期自动清除 |

### 7.5 访问控制与审计

- 服务端按最小权限分配数据库与后台访问权限；健康数据表访问需工单审批 + 操作审计日志〔假设：上线前完成权限矩阵梳理〕。
- 员工后台不提供明文查看用户健康数据的功能（脱敏视图）。
- 安全事件响应：建立数据泄露应急预案，72 小时内完成初步评估与监管/用户告知流程〔假设，等保二级配套要求〕。
