## 一、人力假设与排期前提

| 角色 | 人数 | 覆盖范围 |
|------|------|----------|
| 客户端 Flutter | 2 | iOS + Android 单代码库（D-17），含小组件原生桥（`home_widget`） |
| 后端（NestJS + PostgreSQL + Redis，D-17） | 1–2 | REST API、同步层、推送接入、审核接入 |

| QA | 1 | 测试计划、边界用例、灰度回归 |

> **人力变动即重排**：上述为满编假设。若后端长期只有 1 人，M1 排期中的同步层（D-20）与推送/审核接入需按关键路径重估，预计整体顺延 1–2 周〔假设〕。

**排期前提（与决策记录一致）**：
- MVP 范围 = M1/M2/M3/M7/M8 + **中英双语**（D-15 替换 PRD「MVP 仅中文」假设，i18n 工作量已计入 M1）。

- 登录方式：手机号验证码 + 微信 + Sign in with Apple（D-13，Apple 登录为 iOS 上架强制项）。
- 评审 Gate 准则：必须解决项 1/3/5（计时、营养背书、合规）中，项 1 未关闭不进 MVP 开发；项 3 不阻塞 MVP（M1–M3）但为 V1.1 M4 上线 Gate；项 5 法务 M0 介入、MVP 灰度前签字。

### 2.5 灰度验收标准（进上线 Gate）

- 崩溃率：双端 crash-free users ≥ 99.5%〔假设〕。
- 计时准确性：M2 边界用例（跨午夜/跨时区/回拨系统时间/勿扰下本地通知）全部通过；小组件与 App 内倒计时误差 ≤1 分钟。
- 记录链路：单次记录中位耗时 ≤15 秒（埋点实测）；四态持久化无丢单（待同步队列可恢复）。
- 推送：iOS APNs 送达正常；Android 厂商通道到达率达标（阈值见 5.1 风险表）。
- 合规：法务书面签字（D-18）；隐私弹窗、导出/删除入口、免责声明（中英）全部就位。
- 拍照识别：实测 Top-1/Top-3 达标或已按 D-16 降级为「拍照→手动搜索」。
