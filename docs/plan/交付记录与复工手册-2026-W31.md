## 四、踩坑档案（本周全部实战教训）

### 4.1 环境类（换机必读）
1. **中文路径三杀**：① `flutter analyze` 在中文路径崩溃 → 用 `dart analyze`；② Gradle 读 `local.properties` 的 `flutter.sdk` 按 ISO-8859-1 解码中文乱码 → settings.gradle.kts 已改 UTF-8 逐行解析 + gradle.properties 强制 JVM UTF-8；③ SDK 内 `FlutterAppPluginLoaderPlugin.kt` 同问题已打补丁（.tooling 不入库，**重装 SDK 需重打**，补丁内容见 git 历史或重新按 AGENTS.md 说明处理）
2. **Android 构建**：系统 Java 11 不行，必须 JBR 17+；`jni` 包 1.0.1 与 AGP 9 不兼容（lock 已升 1.0.2）；`flutter_local_notifications` 需 core desugaring（已配）；国内依赖下载卡死 → `USE_CN_MIRRORS=1`（CI 海外 runner 不可开）
3. **iOS**：部署目标已升 15.0；Xcode Accounts 无账号时签名报 "No Account for Team"；**debug 包不能从主屏幕启动**（iOS 14+ 限制），真机日用装 release
4. **模拟器**：访问宿主机后端用 `10.0.2.2` 不是 localhost；`API_BASE_URL` **必须含 /v1**（踩过 404 的坑）

### 4.2 框架/代码类
5. **Flutter 3.44 行为变更**：带 action 的 SnackBar 默认 `persist: true` 永不消失——所有限时吐司必须显式 `persist: false`（撤销吐司 bug 根因，有回归测试 `undo_toast_regression_test.dart`）
6. **slang**：`namespaces: false` 下同 locale 多 i18n 文件互相整份覆盖 → 全项目只有 `i18n/strings_zh-CN.i18n.json` / `strings_en.i18n.json` 两个文件；生成固定 `dart run slang`；`slang_build_runner` 已移除（它会让 build_runner 整体失败）
7. **drift 测试死锁**：流退订的内部 Timer 落 widget 测试假时钟区与 `db.close()` 互等 → 测试体内卸载+多次 pump，close 放 addTearDown（见 record 测试 settleUi 注释）
8. **点中率**：adb 盲 tap 坐标按 uiautomator bounds 取（`adb shell uiautomator dump`），截图显示会缩小勿按显示比例算

### 4.3 产品逻辑类（修复记录，回归测试已锚定）

## 追记（三十八）：v1.15.6——进行中周期全量落盘冻结（「调整断食时间后首页断食不持续」根治）（2026-10-01）

**触发**：真机走查「断食趋势正常，但首页的断食不持续，是不是因为我调整断食时间」。

**根因（结构性盲区）**：`FastingCycleStore.saveActiveCycle` 全仓唯一调用点在 `extend()`——**普通（未延长）进行中周期从不落盘**，完全由当前方案经 `resolveState` 每秒推导。v1.14.x 拍板 B 的「锚点冻结」依赖 stored cycle，实际只保护了延长过的周期。方案变更三条路径（换方案登记即上行 → 下轮 pull「服务端更新且窗口不同」即刻采纳 / T13 转正 / 立即应用）都会替换本地生效方案 → resolveState 按新方案重算落点：当前时刻落新方案进食窗时，进行中断食无声消失（不落任何记录）；不落进食窗时锚点也被重算（终点漂移）。附带第二缺口：杀进程跨过终点时 build 补关闭路径无 stored 可结算，普通周期本地连记录都不落（只靠服务端 ghost autoClose 兜底）。

**修复**（`fasting_timer_controller._resolve`）：stored 缺失且推导快照带进行中周期时**首次观察到即落盘**（`ActiveCycleSnapshot.fromCycle`）——此后锚点冻结分支接管，方案变更不再重算进行中周期，新方案只作用下一周期（D-06 精神不变）；杀进程跨终点由 build reconcile 正常补关闭落记录。关闭/破窗路径的 clearActiveCycle 不变，下一周期首次观察到重新落盘。

**测试**：新增回归「进行中周期未延长也冻结锚点：立即应用新方案后断食按旧锚点持续」（新方案进食窗覆盖当前时刻，无冻结必复现抹除）；既有冻结/关闭/转正用例全过。App **1469** 全绿，`dart analyze` 零 issue。**无服务端改动**。

## 追记（四十六）：断食 makeup 口径全量审计——三条链路对齐「补签计达标、不计时长」（2026-10-04）

**触发**：追记（四十五）后用户拍板「检查其他数据展示相关的页，修复全量类似问题」。

**审计结论**（时长类必须排除 makeup、达标类必须包含 makeup，设计意图本就有 CycleResult.makeup 枚举 + isRealFastResult，但三条链路各有各的走样）：
1. **数据页近 7 日断食折线**（weeklyFastingHoursProvider）：无过滤——补签行（/sync 下行 actualSec 恒 0）画 0 点，与三态格「达标绿」矛盾。修：加 `!deleted && isRealFastResult`。
2. **月报平均断食时长**（monthlyReportProvider 的 fastingHoursByDate map）：无过滤——补签 0 时长拉低平均值。修：同款过滤；weeklyReport/weeklySummary/monthlyReport 的 qualifiedDates 顺带补 `!deleted`（tombstone 不再计入达标天数，与三态格口径一致）。
3. **streak 回填通道**（_backfillRecentFastingRecords）：与 /sync 下行**同记录两种本地形态**——回填把 makeup 塌缩 completedOnTime + actualSec=fastedMinutes（下游 isRealFastResult 过滤形同虚设，补签计划时长混进趋势/累计），且守卫 `actualEndAt==null` 把 makeup 整行跳过（只走回填的设备补签日三态格灰、服务端 streak 已计达标）。修：`localResultNameOf`（保留 makeup 身份）+ actualSec=0 + makeup 放行（end 锚点回落 plannedEnd）+ serverTerminalDates 同款放行；删除旧 `_serverResultName`。
**不受影响面**（口径本就正确）：报告页时长折线/累计成果卡（filter 已存在且随①生效）、三态格/达标率/周报月报达标天数（含 makeup ✓）、连胜/社区连续天数、首页仪表（进行中周期）。
**存量说明**：wcg 的 8 天修复行已由追记（四十五）转正 completed（真实断食），不受本轮影响；他设备上历史回填写入的 makeup→completedOnTime 行无法回辨，按真实断食展示（记录在案）。
