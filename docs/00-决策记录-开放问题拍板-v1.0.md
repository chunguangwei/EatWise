## D-01 北极星指标口径（已定）

- **北极星**：周活跃且完成 ≥4 个「有效记录日」的用户数（WAU-Active）。
- **有效记录日定义**：当日完成断食打卡达标（见 D-08）**或** 当日有 ≥1 条饮食记录。
- PRD 第 1.4 节各项目标值（引导完成率 ≥70%、次日记录留存 ≥45%、7 日打卡留存 ≥30%、记录 ≤15 秒、D21 ≥18%）确认为验收口径，纳入埋点规范统一埋点。

## D-04 每日营养目标（TDEE）公式（待外部背书，开发可并行）

- **BMR**：Mifflin-St Jeor 公式。
  - 男：`10×体重kg + 6.25×身高cm − 5×年龄 + 5`
  - 女：`10×体重kg + 6.25×身高cm − 5×年龄 − 161`
- **TDEE** = BMR × 活动系数：久坐 1.2 / 轻度 1.375 / 中度 1.55 / 高度 1.725。
- **目标热量**：减脂 = TDEE × 0.8；下限保护：女 ≥1200 kcal、男 ≥1500 kcal。维持/作息目标 = TDEE × 1.0。
- **三大营养素配比**（供能占比）：蛋白 25% / 碳水 45% / 脂肪 30%；换算 蛋白 4 kcal/g、碳水 4 kcal/g、脂肪 9 kcal/g。
- 缺基础信息时兜底默认值：女 1800 kcal / 男 2200 kcal，按同配比折算，并引导补全资料。
- 实现要求（评审项 3）：规则引擎封装为**纯函数 + 全量单测 + 公式热配置**；M4 上线前取得营养专业侧书面背书。

## D-05 红黄绿信号灯阈值（待外部背书，开发可并行）

以「当日累计摄入 ÷ 当日目标」的百分比判定：

| 营养素 | 绿（达标） | 黄（提醒） | 红（警示） |
|--------|-----------|-----------|-----------|
| 热量 | 85%–110% | 60%–85% 或 110%–130% | <60% 或 >130% |
| 蛋白质 | ≥90% | 70%–90% | <70%；>150% 标红（提示过量） |
| 碳水 | 85%–115% | 65%–85% 或 115%–135% | <65% 或 >135% |
| 脂肪 | 80%–110% | 55%–80% 或 110%–130% | <55% 或 >130% |

- 一句话建议：MVP 用**规则模板库**（按营养素 × 落区 × 餐段生成，中英双语各一套），不用模型生成。
- 三重编码（颜色+图标+文字）为硬性要求，见 PRD M8。

## D-06 方案更换生效时机（已定）

更换断食方案**次日 0 点（本地时区）生效**，当日已记录数据保留；确认弹窗明示生效时间。

## D-07 断食计时存储与打卡归属日（已定，评审项 1）

- 全部时间戳 **UTC 存储**，渲染按设备本地时区换算。
- **打卡归属日 = 进食窗口所属自然日**（一次断食归入其后的进食窗口那天）。
- 跨午夜、跨时区、回拨系统时间等边界用例与状态机迁移表，详见《规格-M2 断食计时状态机》。

## D-08 断食达标判定与破窗容差（已定）

- 完整走完断食窗口（进食窗口按时开启）→ 当日**达标**。
- 手动「结束断食」提前 ≤15 分钟，或「延长」后最终断食时长 ≥ 计划时长 → 仍记**达标**。
- 提前 >15 分钟破窗 → 当日**不达标**，记录实际断食时长，streak 按 D-12 处理。
- 容差值 15 分钟走服务端配置，可热调。

## D-09 窗口提醒策略（已定）

- 进食窗口**开始前 15 分钟**提醒一次 + **到点**提醒一次；断食窗口开始（进食结束）到点提醒一次。
- 使用本地通知（local notification）实现，不依赖推送通道在线；尊重系统勿扰与用户开关，关闭权限时 App 内顶部横幅引导。
- 提醒提前量与文案（中英双语）均可在设置中调整，默认 15 分钟。

## D-10 「延长」步进与上限（已定）

- 步进 30 分钟，单次最多延长 4 小时；延长后的进食窗口相应后移，不压缩进食窗口时长。

## D-11 记录撤销时间窗（已定）

- 「已记录·撤销」吐司展示 **10 秒**，点击撤销即撤回该条（乐观更新回滚）。

## D-12 Streak 口径与补签卡（已定，评审项 2 强制二选一）

- **口径：以「断食打卡达标」（D-08）为唯一 streak 口径**，不与饮食记录并行计数。饮食记录另有独立的「记录天数」统计，仅展示、不进 streak。
- 中断 → 当前 streak 归零；弹窗同时展示「连胜如何计算」与补签卡状态（可补签/已用尽/已断签三态）。
- **补签卡规则**：每月 1 日发放 2 张，当月有效、月底清零；仅可补最近 7 天内的断签日；库存上限 2 张（不累积）。
- 状态机与规则表详见《规格-M5 streak 与补签卡》。

## D-13 账号登录方式（已修订 v2，2026-09-07）

- **主路径：账号密码注册/登录**（用户名 3-20 位字母/数字/下划线，密码 8-64 位含字母+数字，bcrypt 存储）。
  - 修订原因：短信验证码通道无可靠接收方案，MVP 阶段不可用。
  - 注册即设密码，首次使用无需手机验证；提供「修改密码」模块（验证旧密码，改密后全端重新登录）。
- **备用路径（保留代码，UI 降级）**：手机号验证码（当前为 mock，待短信通道接入后启用）、微信登录、Sign in with Apple（iOS 上架强制要求提供 Apple 登录）。
- Google 登录随英文版海外上架评估（V1.1+），MVP 不做。
- 错误码：AUTH_USERNAME_TAKEN(409) / AUTH_INVALID_CREDENTIALS(401) / AUTH_PASSWORD_TOO_WEAK(400)。

## D-14 最低系统版本（已定）

- **iOS 15+ / Android 8.0（API 26）+**。
- 依据：iOS 15 起 WidgetKit/Live Activity 能力完备（Live Activity 实际需 iOS 16.1+，低版本小组件降级为普通 Widget）；Android 8 起通知渠道、后台限制机制稳定。Live Activity 为 iOS 16.1+ 增强项，非阻断。

## D-15 国际化：中英双语（已定，替换 PRD「MVP 仅中文」假设）

- **MVP 即支持简体中文 + 英文双语**：默认跟随系统语言，设置内可手动切换；文案全部走 i18n key 管理，禁止硬编码。
- 范围：UI 文案、信号灯建议、推送/本地通知、趣味文案、食物库条目（中英双语名称+别名）、日期/时间/数字格式本地化。
- 社区内容（UGC）MVP 不分语言圈，全量混排；V1.1 再评估。
- 上架区域（已修订 v2，2026-09-08）：**海外 App Store 首发，服务器海外部署**；中国区上架与国内 App 备案/ICP 均不适用。GDPR 为主合规框架（D-18 v2）。Google 登录纳入 V1.1 评估（D-13 原定口径）。
- 详细规范见《规格-i18n 中英双语》。

## D-16 食物库与识别服务选型（已定）

- **食物营养库**：MVP 自建核心库（基于《中国食物成分表》标准版 + USDA FoodData Central 公共数据清洗合并），中英双语条目，MVP 规模 ≥3000 条高频食物，覆盖每 100g 热量/蛋白/碳水/脂肪 + 别名。
- **拍照识别**：MVP 接入第三方食物识别 API（选型基准：Top-1 ≥70%、Top-3 ≥90%，用真实餐食样本上线前实测，未达标则该入口降级为「拍照→手动搜索」）；识别**异步不阻塞主流程**，手动搜索 + 常吃复用为一级兜底。
- **语音识别**：用系统 ASR（iOS Speech framework / Android SpeechRecognizer）+ 自研轻量解析（食物库词典匹配 + 份量正则），不引入独立 NLP 服务。
- 撤销窗、置信度低标「请确认」等交互规则见 PRD M3。

## D-17 技术栈与双端架构（已定）

- **客户端：Flutter（稳定版 3.x）单代码库出 iOS + Android 双端**。
  - 理由：双端 UI 一致性（设计稿跨触点一致性 ≥95% 的要求）、渲染性能、单团队维护成本；Token/主题体系（CSS Custom Properties 语义）可直接映射为 Flutter ThemeExtension。
  - 关键依赖：状态管理 Riverpod；本地存储 SQLite（drift）；网络 dio；i18n slang/intl；本地通知 flutter_local_notifications；小组件 iOS WidgetKit(+Live Activity) / Android AppWidget 经 `home_widget` + 原生桥实现。
- **后端**：Node.js（NestJS）+ PostgreSQL + Redis；REST API（契约见《技术-后端 API 契约》）。
- **推送**（已修订 v2，2026-09-08）：APNs + FCM 直连；国内厂商通道与聚合推送 SDK 不适用（海外首发，D-15 v2）。
- **内容审核**（已修订 v2，2026-09-08）：文本/图片先审后发不变（转人工队列保留）；供应商改海外可用服务（如 AWS Rekognition / Google Vision SafeSearch / Hive，M0 重定），阿里云/腾讯云内容安全仅限国内链路，不适用。

## D-18 隐私合规（待外部背书，法务 M0 介入）

- 适用法规（已修订 v2，2026-09-08）：**GDPR 为主**（海外首发，D-15 v2）——隐私政策英文终稿、数据导出/删除（已实现 U3/U5，需按 GDPR Art.15/17 复核）、DPA 与 sub-processor 清单、EU 代表（Art.27，如适用）、Apple App Privacy 标签填报；国内 PIPL 口径保留备查（中国区上架时再启用）。
- 落地要求：最小化收集、明示授权（首次启动隐私弹窗）、数据可导出/可删除（设置内入口）、全程「非医疗建议」免责声明（中英双语）、SDK 与权限清单公示。
- 详见《合规-隐私与合规方案》。

## D-19 硬件/可穿戴接入（已定）

- MVP 与 V1.1 均不做；V1.2 后根据用户反馈再评估，本周期内不预留强耦合设计。

## D-20 数据同步策略（已定，评审项 4）

- 本地优先（offline-first）+ 云端同步；记录四态持久化：提交中 / 已同步 / 待同步 / 冲突。
- 冲突合并：字段级 LWW（Last-Write-Win，以服务端时间戳为准）+ 冲突队列；不可合并字段（如已删除又修改）保留双份并人工提示。
- 幂等：客户端生成 `clientRequestId`，服务端去重；记录页/我的页提供「待同步 N 条」可见入口。
- 详见《规格-数据同步与四态持久化》。
