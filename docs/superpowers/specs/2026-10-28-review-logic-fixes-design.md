# Review 逻辑修复设计

用户已批准 2026-10-28 审查列出的五类缺陷及发布稿件保护。本设计细化实施约束，技术选择由实现方承担。

## 目标与行为

1. 自定义食品创建先持久化身份及冻结请求；响应未知时保持原请求键，先确认创建身份再补传最新编辑。后台旧回执不能把新编辑标为已同步；离线编辑最终补传，不重复建食品。单食品上行串行；账号和会话继续隔离，引用记录在同事务改映射。
2. 编辑 404 使用已有 batch-get 存续核验。确实晋升共享才标 approved；已删除/不可访问时给精确反馈、保留可恢复操作，不虚构共享或静默删除未同步记录。
3. 举报后的临时下架可被管理员确认下架并结案，也可恢复上架；保留历史举报计数，待复核筛选依据未处理队列，而非历史计数。决定与出队同 post 锁事务；重复已结案决定仍幂等或明确冲突。
4. 报告只对真实进行中周期的正式归属日标记进行中；未进入报告窗口的明日周期不能标为今天。依赖计时器的语义状态变化，避免仅监听 prefs 句柄。
5. Android/iOS 读取系统 IANA 时区标识，启动、系统时区变更和回前台时刷新；统一渲染、X-Timezone 与提醒排程。保留进行中周期 UTC 锚点；失败回落须安全，不再用当前 offset 猜地区。优先复用原生 MethodChannel，不新增第三方依赖。
6. 社区发布从首个提交 await 前冻结稿件，提交时文字/图片/匿名/头像等不可修改，按钮防重复；失败恢复编辑与草稿，成功退出只对应提交的稿件。

## 约束

- `.tooling/flutter/bin` Flutter 3.44.8 / Dart 3.12.2；使用 dart analyze，禁止 flutter analyze。
- Flutter 测试、生成、预览及原生构建由 root 串行执行，避免 SQLite native asset 冲突。
- 数据迁移保留所有现有记录；新增可空快照按版本增量迁移，旧 pending 身份不丢弃。
- 不修改营养目标、断食判定/补签、活动汇总等已定产品规则。
- i18n 只改两份 JSON，以 dart run slang 生成；普通正文用高对比语义 token。
- 用户要求 HTTPS/SSH 超时暂不处理：不继续线上连接排查或生产业务写入。
- 本轮先完成实现、回归、构建及 GitHub 代码更新；发布状态必须区分客户端产物与尚未部署的服务端行为。

## 验证

真实 SQLite + Completer 固定创建/编辑竞态；重启及丢回执后不重复创建；迁移与账号隔离回归。服务端内存与本机 PostgreSQL 验证举报结案、重放、回滚和筛选。报告覆盖跨午夜、明日归属及新周期响应。时区覆盖纽约 DST、同 offset 不同地区、系统变更与前台刷新、平台失败回落。发布页覆盖在途锁定、失败恢复、中英与小屏大字体。
