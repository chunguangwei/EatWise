# 食物份量说明与图片帖人工审核

用户已同意上一轮建议中的前两项优化，并补做真机专项。沿用 Flutter、NestJS 与现有设计系统，不引入审核供应商或新的营养阈值。

## 食物详情

- 用所选合法份量的热量占当前每日目标比例替代单食物红绿灯与“放心吃/尽量别吃”。该比例是参考信息，不是健康等级，不改变每日目标或 D-05 当日累计判定。
- 原有每 100g 营养与供能比例保留。非法/空份量不显示伪造的本份占比，继续禁用确认。
- 来源只基于实际持久字段识别食物库、个人填写、社区贡献、AI 估算或来源不明，不编造权威数据来源。估算提示用户核对。
- 移除详情食物热量换算“需走几步”的抵消表达；每日活动与摄入既有口径不变。
- 采用现有语义颜色和卡片，覆盖中英、亮暗、小屏、2 倍字号及键盘留白。

## 社区图片帖

当前 D-17 v3 是开放发布策略，关键词桩没有接入社区发布。新规则仅将含图片帖子改为 pending，纯文字仍按现行流程直接发布。图片帖在审核通过前只在作者的帖子视图中展示，使用现有人工审核队列；不声称已做自动图片识别。

- 创建帖子、待审队列与幂等回执同事务；重复请求只有一条帖子和待审事件。
- 审核通过后公开，拒绝后保持作者可见的说明；删除/审核结案清理队列，事务失败不留下半完成状态。
- 发布页带图时告知审核规则并显示“提交审核”；按服务端 pending 响应给出提交成功提示。原有待审徽标保留。
- D-17 与涉及发布可见性的事实说明同步，不引入付费审核渠道或新的第三方数据传输。

## 真机专项

生产 iPhone 的账号与记录必须保留。演示数据只用本地 memory 服务及隔离测试应用；如无法安全建立隔离环境，不对生产包运行写数据的走查脚本。

先验证连续输入、保存后下一条输入、键盘遮挡和发布反馈。AI 识别能力需要真实模型、样本与支持设备，只有实际运行的结果才能标为通过。没有安卓设备或模型时明确记录未验范围。
