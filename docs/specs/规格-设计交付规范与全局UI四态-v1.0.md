# 第一部分 · 设计交付规范

## 1.1 Figma 图层命名：模块 / 组件 / 状态三级

**规则**：所有可交付图层（Frame、组件实例、切图分组）统一采用三级命名，斜杠分层，全部小写英文 kebab-case，禁止中文、空格、随意编号（如「矩形 237」）。

```
{模块码}/{组件名}/{状态}
例：m2-home/stat-ring/fasting
    m3-record/food-card/default
    com/btn-primary/pressed
```

| 层级 | 取值 | 规则 |
|------|------|------|
| ① 模块码 | `m1-guide`（新手引导）/ `m2-home`（首页计时）/ `m3-record`（记录）/ `m4-data`（数据）/ `m5-community`（社区）/ `m6-report`（报告）/ `m7-me`（我的）/ `m8-a11y`（无障碍走查页）/ `com`（全局通用） | 与 PRD 模块编号 M1–M8 一一对应；跨模块通用组件一律归 `com` |
| ② 组件名 | 见 3.4 组件层级：`container / grid / section / card / stat-ring / signal-card / btn / input / fab / tab-bar / toast / skeleton / empty-state / dialog / banner` 等 | 与第二部分 Token 映射表中的 Flutter 组件命名同源，禁止同义异名（如不许 `button` 与 `btn` 混用） |
| ③ 状态 | `default / hover / focus / pressed / disabled / loading / empty / error / success / selected / unselected` | 状态词只准从上表取；四态标准件（第三部分）必须用 `loading/empty/error/success` |

**验收**：交付前跑 Figma 图层 lint（插件如 Design Lint / 自查脚本），三级命名覆盖率 = 100%，无「未命名/矩形 N/编组 N」残留。

## 1.2 组件结构与变体（Variants）规则

| 规则项 | 规范 |
|--------|------|
| 组件归属 | 全局组件（按钮/输入/卡片/吐司/骨架/四态件）建在 `com` 库文件，模块页只许引用实例，禁止 detach 后本地改样式 |
| Variant 属性名 | 只允许五个标准属性：`State`（见 1.1 状态词表）、`Size`（`sm/md/lg`）、`Theme`（`light/dark`）、`Platform`（`ios/android`，仅确有差异的组件使用）、`Content`（`with-icon/icon-only/text-only` 等布尔型内容开关） |
| 属性值顺序 | State 按 default→hover→focus→pressed→disabled→loading 排列；Size 按 sm→md→lg |
| 布尔开关 | 图标、徽章、CTA 等可有可无元素用布尔属性（如 `showIcon`），不新增 Variant 维度 |
| 嵌套深度 | 组件嵌套 ≤3 层（基础件 → 复合件 → 区块）；超过 3 层必须拆分为区块模板 |
| 状态全覆盖 | 交互组件（btn/input/fab/card）必须提供 `default/pressed/disabled/loading` 四态 Variant；`focus` 态由开发统一实现（2px 轻盈绿 focus 环，见设计稿 4.3），Figma 可不出稿 |
| 自动布局 | 所有组件启用 Auto Layout，padding 只许填 4pt 阶梯值（见 1.4），禁止裸拖绝对定位 |

## 1.3 切图导出规范

### 1.3.1 格式选择

| 素材类型 | 格式 | 说明 |
|----------|------|------|
| 图标（线性 2px 圆角、面性状态图标、信号灯图标） | **SVG** | 矢量，双端无损缩放；Flutter 端经 `flutter_svg` 渲染〔假设：依赖选型，M0 技术评审确认〕 |
| 复杂插画（空状态插画、引导页主视觉、信号灯拟人） | **SVG 优先**，含照片级渐变/纹理时退用 PNG | SVG 体积 >200KB 或含位图滤镜时改用 PNG |
| 摄影/静物素材（打卡默认图、营销图） | **WebP**（Android）/ **PNG @1x/@2x/@3x**（iOS 侧通用包用 PNG） | Flutter 统一打包时用 PNG 三档，构建期转 WebP 由 CI 决定〔假设〕 |
| App Icon、启动图、小组件预览图、通知图标 | 走原生通道（见 1.3.3），不进 Flutter assets | 属平台强制规格 |

### 1.3.2 倍率与双端命名映射

Flutter 端统一采用 **1x 基准 + 分辨率变体目录**；原生侧（小组件、通知、App Icon）按下表映射。

| 倍率 | Flutter 目录 | Android drawable | iOS Asset Catalog | 典型用途 |
|------|--------------|------------------|-------------------|----------|
| 1x | `assets/images/` | `drawable-mdpi` | `@1x` | 基准图（必出） |
| 1.5x | `assets/images/1.5x/` | `drawable-hdpi` | —（iOS 无此档） | 低端 Android 兼容（可选） |
| 2x | `assets/images/2.0x/` | `drawable-xhdpi` | `@2x` | 主流机型（必出） |
| 3x | `assets/images/3.0x/` | `drawable-xxhdpi` | `@3x` | 高分屏（必出） |
| 4x | `assets/images/4.0x/` | `drawable-xxxhdpi` | — | 仅大于 200px 的关键位图出（可选） |

**文件命名**（Flutter assets 与原生 drawable/asset 同源规则）：

```
{类型}_{模块码}_{名称}[_{状态}].{ext}
类型：ic（图标）/ img（插画·照片）/ logo / anim（动效）
例：ic_m2_timer_pause.svg
    img_m3_empty_record.png     → assets/images/、1.5x/、2.0x/、3.0x/ 同名
    ic_com_signal_green.svg
```

- 全部小写 snake_case；模块码同 1.1；`com` 前缀为全局件。
- Android 原生侧同名同义直接落 `drawable-*`（合法字符天然满足）；iOS 原生侧进 `Assets.xcassets`，Asset 名与文件名同名（不带扩展名）。
- **双端一致性约束**：同一逻辑素材双端文件名必须一致，差异只允许体现在目录/后缀（`@2x` vs `2.0x/`），禁止双端各自起名。

### 1.3.3 原生通道素材（不进 Flutter assets）

| 素材 | iOS | Android |
|------|-----|---------|
| App Icon | App Store 1024×1024 + Assets.xcassets 全尺寸 | `mipmap-*` 48–192dp + Play 512×512，含自适应图标前景/背景层 |
| 启动图 | LaunchScreen storyboard 用图 | `drawable-*` + `windowBackground` |
| 小组件 | WidgetKit 预览图进 Assets.xcassets | AppWidget 预览图进 `drawable-*` |
| 通知小图标 | —（APNs 用 App Icon） | `drawable-*` 单色剪影（alpha 通道，禁止彩色） |

## 1.4 标注规范

| 标注项 | 规范 | 禁止 |
|--------|------|------|
| 间距 | **一律标注 4pt 阶梯 Token 名**（`space-1`…`space-16`，见 2.6），Figma Dev Mode 中数值必须能整除映射到阶梯 | 禁止只标像素裸值（如「13px」）；出现非阶梯值即视为设计稿缺陷，打回修正 |
| 色彩 | 标注 Token 语义名（`--brand-primary`、`--signal-green`…），不标 HEX；HEX 仅以 Token 表为唯一真源 | 禁止在页面上贴未入 Token 表的「临时色」 |
| 字号 | 标注文字样式名（`text-base16` 等）+ 字重 + 行高 | 禁止仅标 px |
| 圆角/阴影 | 标注 Token 名（`radius-md12` / `shadow-sm`） | 同左 |
| 状态说明 | 交互流程在页面旁挂「状态注释」便签：触发条件 → 目标状态 → 文案 key（i18n key，D-15 禁止硬编码） | 禁止把交互逻辑只存在口头/聊天记录 |
| 度量基准 | 设计稿基准画布 375×812（iOS）/ 360×800（Android），标注以 dp/pt 为单位，1pt = 1dp = 1 基准单位 | 禁止按物理 px 交付 |

## 1.5 设计走查 Gate 流程

**原则：走查通过方可提测。** 每个版本每个模块执行一次，输出走查单（下文模板）归档。

```
设计交付 → 开发实现 → ①还原度走查 → ②对比度走查 → 双通过 → 提测（QA）
                        ↘ 任一不通过 → 打回修复 → 重新走查
```

### ① 还原度走查

| 检查项 | 方法 | 通过标准 |
|--------|------|----------|
| Token 命中率 | 代码扫描：颜色/字号/圆角/间距硬编码值检查（lint 规则，见 2.1） | 硬编码 = 0，Token 引用率 100% |
| 间距还原 | 截图叠加设计稿比对 | 间距偏差 ≤2dp，且落在 4pt 阶梯上 |
| 字号/字重/行高 | 逐页文字样式比对 | 与 Token 表完全一致 |
| 组件结构 | 对照 Figma 组件层级 | 组件嵌套、状态 Variant 与设计一致 |
| 双端一致 | 双端同页截图并排比对 | 符合第五部分 ≥95% 度量 |

### ② 对比度与无障碍走查（硬性，对齐 PRD M8 / 设计稿 4.3）

| 检查项 | 方法 | 通过标准 |
|--------|------|----------|
| 文字对比度 | 取色器实测前景/背景 | 正文 ≥4.5:1（WCAG AA）；大字（≥18pt/14pt Bold）≥3:1 |
| 信号灯三重编码 | 逐实例检查 | 颜色 + 图标 + 文字三者齐备，绝不单靠颜色 |
| 触控目标 | 布局检查 | 交互元素 ≥44×44dp，语音按钮 ≥48dp |
| 字号放大 | 系统字号调至 200% 回归 | 正文最小 14pt 等效，布局不截断不重叠（截断规则见 4.1） |
| focus 态 | 键盘/读屏遍历 | 全局统一 2px 轻盈绿 focus 环，完整 ARIA/语义标签 |
| 减弱动效 | 开启系统「减弱动态效果」 | 非必要动效全部降级为静态/淡入（对齐设计稿 5.1 降级方案） |
| 暗色主题 | 切暗色全页走查 | 全部组合仍达 AA（暗色 Token 见 2.7） |

**走查单模板**（每次走查填一行）：版本号 / 模块 / 走查人 / 日期 / ①各项结果 / ②各项结果 / 结论（通过·打回） / 遗留问题链接。

# 第二部分 · Token 映射表（设计 Token → Flutter ThemeExtension）

## 2.1 架构约定

- 按 D-17，设计稿 CSS Custom Properties 语义整体映射为 Flutter `ThemeExtension`，四类扩展〔假设：类名与文件结构，待客户端工程初始化时确认，本表字段名为唯一约定〕：

| ThemeExtension 类 | 承载内容 | 访问方式 |
|-------------------|----------|----------|
| `AppColors` | 全部色彩 Token | `Theme.of(context).extension<AppColors>()!.brandPrimary` |
| `AppTextStyles` | 字号/字重/行高 | 同上 |
| `AppRadii` | 圆角 | 同上 |
| `AppShadows` | 阴影 | 同上 |
| `AppSpacing` | 间距常量（`static const double`，可为普通常量类） | `AppSpacing.s4` |

- **铁律**：代码中禁止出现裸 `Color(0xFF…)`、裸字号/圆角/间距数字；CI 挂 lint（自定义 `avoid_hardcoded_design_values` 规则）拦截，命中率要求 100%（1.5 还原度走查第 1 项）。
- 亮/暗/跟随系统三主题：`AppColors` 提供 `light` / `dark` 两套实例，`ThemeMode` 持久化用户偏好（对齐设计稿 3.5「偏好本地持久化」）。

| `--brand-accent` | `#FF9F45` 暖阳橙 | `brandAccent` | 进食窗口、成就/打卡、FAB |
| `--signal-red` | `#FF6B6B` 活力珊瑚 | `signalRed` | 红灯预警、营养超标 |
| `--signal-yellow` | `#FFD24C` 提示黄 | `signalYellow` | 黄灯·适量提示 |

## 2.6 间距 Token（4pt 阶梯，源自设计稿 3.3）

| 设计 Token | 值（dp） | Flutter 常量（`AppSpacing`） | 约定场景 |
|------------|----------|-------------------------------|-----------|
| `--space-1` | 4 | `s1` | 图标与文字间隙 |
| `--space-2` | 8 | `s2` | 紧凑元素间距 |
| `--space-3` | 12 | `s3` | 卡片内行距 |
| `--space-4` | 16 | `s4` | **卡片内边距**、栅格 gutter、安全边距 |
| `--space-6` | 24 | `s6` | **区块间距** |
| `--space-8` | 32 | `s8` | **页面区段** |
| `--space-12` | 48 | `s12` | 大留白、按钮高度基准 |
| `--space-16` | 64 | `s16` | 首屏大留白 |

- 栅格：移动 4 列 / 平板（md768）8 列 / 桌面（lg1024，仅 Web 后台）12 列，gutter 16、安全边距 16。
- 代码层一律用 `AppSpacing.sX` 或 `SizedBox(height: AppSpacing.s4)` / `EdgeInsets.all(AppSpacing.s4)`，禁止裸数字（lint 强制）。

## 2.7 暗色主题

- 结构：同名字段、双实例（`AppColors.light` / `AppColors.dark`），组件零感知切换。
- 暗色具体色值设计稿未定义〔待外部确认：设计侧需输出暗色 Token 表，输出前开发按以下推导规则占位〕：
  - 背景反转为深灰绿系（`bgPrimary` ≈ `#121817`），文字反转（`textPrimary` ≈ `#F7F9F8`）；
  - `signal*` 三色保持色相、提升亮度以保证深底 AA；
  - 品牌色不变（`brandPrimary` 仍 `#3DBE8B`）。
- 门禁：暗色组合同样过 1.5 对比度走查，未达标不上线。

# 第三部分 · 全局 UI 四态标准件

## 3.1 四态定义与页面级状态迁移

四态 = **加载（loading）/ 空（empty）/ 错误（error）/ 成功（success）**，是所有「依赖数据渲染的页面/区块」的统一状态机（对齐评审建议改进项 3：将现有加载态/空状态扩展为统一四态标准件）。

| 当前态 | 事件 | 迁移至 | 规则 |
|--------|------|--------|------|
| （进入页面） | 发起数据加载 | loading | 骨架屏立即出现，禁用无数据操作；本地有缓存时直接渲染缓存 + 顶部静默刷新，**不**进骨架（避免闪烁） |
| loading | 数据返回且有内容 | success | 骨架整块替换为真实布局，不做逐项渐变（跳动扣分） |
| loading | 数据返回且无内容 | empty | 空 ≠ 错误，不显示重试，显示引导 CTA |
| loading | 请求失败/超时（〔假设〕10s 无响应） | error | 见 3.2 错误分级 |
| error | 点击重试 | loading | 重试最多自动 1 次，之后仅手动 |
| success | 下拉刷新失败 | success（保留）+ 顶部错误 toast | 已有内容时失败不清空页面 |
| success | 数据被清空（用户删除全部记录等） | empty | 无需经过 loading |
| empty | 完成首次操作（如首次记录） | success | 乐观更新直接入账（PRD M3） |

**统一约束**：

- 任何页面四态齐全方可提测（逐模块清单见 3.4，纳入 1.5 走查单）。
- 四态文案全部走 i18n key（D-15），语气遵循品牌语气（鼓励而非命令，设计稿 2.4）。
- 四态切换动效尊重 `prefers-reduced-motion`：降级为直接切换，无位移动画。

## 3.2 四态标准件规范

### 3.2.1 加载态 · 骨架屏（`com/skeleton/*`）

| 项 | 规范 |
|----|------|
| 形态 | 骨架轮廓与真实布局 1:1 同构（同卡片数量、同圆角、同间距 Token），禁用「菊花转圈」作为页面级加载 |
| 颜色 | 底色 `bgSecondary`（卡片位），骨架块用中性浅灰〔假设：`#E4EAE8`，设计稿未给骨架色〕，明暗呼吸动画（opacity 0.5↔1.0，周期 1.2s） |
| 减弱动效 | 静态骨架，无呼吸动画 |
| 局部加载 | 列表分页加载用行内骨架行（2–3 行），不用全屏骨架 |
| 超时 | 〔假设〕10s 未返回 → 转 error 态 |

### 3.2.2 空态（`com/empty-state/*`）

统一结构：**插画（顶部，线性 2px 圆角风格，对齐品牌图标系统）→ 主文案（textXl）→ 副文案（textSm，`textSecondary`）→ CTA 主按钮（可无）**。

| 模块场景 | 主文案（中 / EN） | CTA | 备注 |
|----------|--------------------|-----|------|
| 记录页无记录 | 「肚子的故事还没写呢，点橙色按钮记一笔？」/ "No meals logged yet — tap the orange button to start." | 「记一笔」（跳记录入口） | 文案取自设计稿 5.2 文案库 |
| 数据页当日无记录 | 「数据曲线正在热身，多记几天它就跑起来啦。」/ "Your trends are warming up — log a few days to get them moving." | 「去记录」 | **不显示任何信号灯**（PRD M4：不显示误导性信号灯） |
| 社区打卡流为空 | 「这里在等今天第一口美食登场。」/ "Waiting for today's first check-in to show up." | 「发布打卡」（P1 起） | 同时可插 1–2 张官方示例卡〔假设〕 |
| 我的-补签卡为 0 | 「本月补签卡已用完，下月 1 日会发新卡哦。」/ "No make-up cards left — new ones arrive on the 1st." | 无 CTA | 对齐 D-12 补签卡规则 |
| 搜索无结果 | 「没找到这个食物，换个关键词试试？」/ "No match — try another keyword?" | 「手动添加」 | 记录兜底链路（PRD M3） |

### 3.2.3 错误态（`com/error-state/*`）

分级处理，结构：**图标（信号灯红图标+文字，三重编码）→ 错误说明 → 重试按钮（主按钮）→ 次级出口（可选）**。

| 错误类型 | 触发 | 文案（中 / EN） | 按钮 | 降级 |
|----------|------|------------------|------|------|
| 无网络/弱网 | 请求网络层失败 | 「网络开小差了，检查一下网络再试试～」/ "Connection hiccup — check your network and retry." | 「重试」 | 记录链路走本地暂存（D-20 待同步），只读页显示缓存 + 横幅 |
| 服务端错误（5xx/超时） | 请求失败 | 「服务有点累啦，稍后再试一次？」/ "Our servers are catching a breath — try again in a moment." | 「重试」 | 同上 |
| 识别失败（拍照/语音） | 识别服务无结果/低置信 | 「没认出来这道菜，手动搜一下也很快！」/ "Couldn't recognize that dish — a quick search works too." | 「手动搜索」 | 一级兜底：手动搜索 + 常吃复用（D-16），识别异步永不阻塞主流程 |
| 权限拒绝 | 系统权限弹窗拒绝 | 见 4.3 权限降级表 | 「去开启」 | 见 4.3 |
| 同步冲突 | 云端合并冲突（D-20） | 「这条记录在另一台设备上改过了，请确认保留哪份。」/ "This entry was edited on another device — pick which version to keep." | 「保留此设备」/「保留云端」 | 不可合并字段保留双份 + 人工提示（D-20） |

统一禁止：不展示技术错误码原文；错误码仅进日志与「复制诊断信息」入口（我的-设置）。

### 3.2.4 成功态（`com/toast`、庆祝微交互）

## 3.3 与数据同步四态的关系（D-20）

页面级四态（3.1）与 D-20 的**记录级**同步四态（提交中/已同步/待同步/冲突）是两个层级，不可混用：

| 层级 | 状态集 | 呈现 |
|------|--------|------|
| 页面/区块 | loading / empty / error / success | 整块骨架、空态页、错误页、正常内容 |
| 单条记录 | 提交中 / 已同步 / 待同步 / 冲突 | 记录卡片右上角状态徽标：提交中=细进度条；已同步=无标（默认态不打扰）；待同步=灰色云图标+「待同步」文字；冲突=红色警示图标+「需确认」文字（均三重编码） |
| 全局聚合 | 待同步 N 条 | 记录页顶部与「我的」页常驻可见入口（D-20 硬性要求）：「待同步 N 条，点击重试」横幅，N=0 时隐藏 |

# 第五部分 · 双端一致性验收（跨触点一致性 ≥95%）

## 5.1 度量方式

**定义**（承接设计稿 4.3「跨触点一致性 ≥95%」）：

```
一致性 = Σ(各检项得分 × 权重) / Σ权重 ≥ 95%
单项得分 = 通过检点 ÷ 总检点（按检点粒度计，非按页面）
```

- **触点范围**：iOS App、Android App、iOS 小组件、Android 小组件、通知（本地/推送）、分享图卡、空态/插画素材。
- **检点池**：每个触点对核心 5 页（首页/记录/数据/社区/我的）+ 四态标准件 + 组件库逐项检查，单版本检点 ≥200 个〔假设：具体检点数由首版走查单确定，后续冻结为基准〕。
- **平台差异白名单**（不计入不一致项，其余差异全部计）：系统字体渲染微差、状态栏/导航栏、键盘、系统日期/时间选择器、返回手势（iOS 侧滑 / Android 返回键）、系统权限弹窗、小组件平台规格（4.5）、触觉反馈差异。

| 检项类别 | 权重 | 度量方法 | 通过线 |
|----------|------|----------|--------|
| Token 值（色彩/字号/圆角/阴影/间距） | 40% | 代码扫描 + 双端截图取色比对 | **100%**（Token 项无 95% 容差） |
| 组件结构与状态行为 | 25% | 对照 Figma Variant 与 1.1 状态词表逐组件走查 | ≥95% |
| 交互流程（步骤数、四态迁移、手势） | 20% | 双端并行操作录屏比对，对照 3.1 状态迁移表 | ≥95% |
| 文案与语义（i18n key 一致、语气一致） | 10% | 抽查各模块核心文案 key | 100% key 同源，双端仅语言文件差异 |
| 素材与插画（同源文件、风格 2px 圆角线性） | 5% | 文件名/内容 hash 比对（1.3.2 同源约束）+ 视觉走查 | ≥95% |

**节奏**：每个发版候选（RC）做一次全量走查；日常迭代按变更模块做增量走查；结果写入走查单（1.5 模板），<95% 不发布。
