# 连续录入输入连接修复（v1.17.6+136）

## 问题与根因

用户反馈记录一笔食物后无法继续输入。v1.17.5 的异步代际保护仍然需要保留，但它没有覆盖布局更新造成的输入控件销毁。

记录页 Column 内存在多个未设 key 的 Padding；键盘弹起会移除入口卡，待同步状态还会插入/移除提示。Flutter 按类型匹配同级节点时可能把搜索框父节点匹配到其他 Padding，导致 EditableTextState 销毁、输入连接重建。新测试在 Android 与 iOS 平台配置均明确捕获原输入实例变为 defunct。给搜索区域最外层 Padding 增加稳定 key，保留整个编辑子树；只给内部 TextField 加 key 无法解决父级被替换。

拍照/语音共用的多食物确认表也有同类问题：移除前一项后，未设 key 的行会按位置复用，把焦点和编辑状态迁移到另一种食物。按 _MealRow 对象身份设置 ObjectKey，保留仍存在的食物行与输入连接。对象身份也能区分同名食物，并允许相似食物替换而不重置份量编辑。

## 输入逻辑检查范围

- 搜索/详情份量/连续确认：保留异步搜索、草稿代际和 FocusNode 身份检查；增加真实键盘消息方式的回归。
- 拍照与语音多行确认：修复删除行时的编辑身份迁移。
- 手动/端侧语音、AI 估算与营养表 OCR、自定义食物、扫码补录：检查现有编辑代际与迟到回填保护。
- 饮水/体重、运动/截图、登录注册/改密、身体档案、AI 设置、社区正文：检查控制器生命周期、动态条件节点、异步回填与焦点调用。
- HomeShell、AppBottomSheet：验证键盘避让及通知关闭行为；HomeShell 实验中输入实例保持稳定，未修改其布局。

## 回归证据

1. 已有待同步记录时点击搜索并弹出键盘，Android/iOS 均保留原 EditableTextState、焦点与键盘连接。

3. 编辑第二项份量时删除第一项，第二项编辑状态保留，后续输入仍写入正确的食物。
