# 同步与产品逻辑复核（2026-10-29）

基线：v1.17.15，提交 ae2b3fa。范围：近期共享食品入账、手动/前台重试，以及相邻的账号隔离、撤销/编辑/删除、健康活动汇总和产品状态提示。没有改动营养规则和断食规则。

## 确认的问题

1. **离线删除丢失同步入口与自动重试条件**：原计数排除所有 deleted 行，手动结果也只查未删除的 pending 行。删除最后一条记录后提示消失，失败删除甚至被报告成功。创建/编辑/删除改为统一待上传查询；只有有服务端身份或未知 create 快照的未确认删除才计入。明确的服务端 tombstone 不再次发删除。
2. **食物搜索跨登录会话缓存污染**：请求拦截器只保护 HTTP 请求与回包，搜索本地查询等待和后续缓存事务未绑定会话。换号可能使用新账号凭据、按旧 owner 缓存；同账号重登的旧响应仍可写入。整个搜索绑定 uid/epoch，并在异步边界检查，事务内过期回滚。
3. **iOS 健康只读权限误判**：已安装 health 13.3.2 的 iOS 原生实现对 READ 返回 nil。原网关将 null 转成 false，下一次刷新就进入 denied 并清空系统活动快照。保留未知权限状态，仅明确 false 阻止读取；仍须应用内单独同意，关闭同步后旧读取不得回填。连接成功不宣称权限已获授予。

平台依据：[Apple HKAuthorizationStatus](https://developer.apple.com/documentation/healthkit/hkauthorizationstatus)。读取被拒与没有数据不能由应用区分；不推测授权，不申请额外写权限。
