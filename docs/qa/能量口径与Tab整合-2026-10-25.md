# 能量口径与 Tab 整合审查

## 审查结果与统一设计

沿用 Flutter 五 Tab 结构与既有品牌。重点审查 D-04/D-19、营养目标纯函数（Dart/TypeScript）、系统健康摘要、手动运动汇总、首页指标、数据日期切换、记录入口和报告导航。

| 问题 | 调整 |
| --- | --- |
| 把摄入减活动消耗称为“结余”，漏掉静息代谢 | 删除结余计算和显示，活动单独作参考；摄入仅与每日摄入目标对照 |
| 系统日汇总直接加手动/截图记录，可能同一运动算两次 | 系统有效汇总优先，缺失时采用手动汇总；手动能量另列并注明未叠加 |
| 首页不估步数能量、数据页却估算，两页不同 | 共用 activitySummaryProvider；系统缺能量时不再把步数粗估当作能量数据 |
| 历史日期配今天运动 | 历史日隐藏今天活动卡；历史摄入标明与当前目标比较 |
| 跨午夜内存中仍保留昨天系统摘要 | 监听 localDayProvider，销毁旧控制器和迟到响应，清旧快照重读；切到首页/数据页刷新 |
| 最低摄入保护后仍按原大缺口预测日期 | 两端按目标热量实际允许的缺口反算速率和参考日期；无正缺口时不给计划日期；保留既有摄入下限 |
| 目标、记录、报告入口分散 | 首页活动卡直达今天的数据；数据页上方统一摄入与目标卡，链接既有身体档案；报告入口放趋势下方可见文字按钮 |

### Tab 职责

- 首页：断食状态与今日简要指标，点击活动卡定位今天的数据页。
- 记录：食物、饮水、体重、运动录入及记录纠错，沿用已有入口和输入保护。
- 数据：摄入目标对照 → 营养信号与明细 → 今日活动来源 → 近七日趋势 → 深度报告。当前目标不是历史目标快照；明确标注。
- 社区：保留交流、屏蔽与举报路径，不把公共帖子混入个人健康统计。
- 我的：保留档案、断食方案、健康同步授权、运动目标、账号和隐私管理；数据页复用档案入口，不再建另一套目标设置。

## 营养口径依据与限制

- Apple 对活动热量的定义是静息基础之上的能量，不等于全天总能量：[Apple 心率与能量估算说明](https://www.apple.com/health/pdf/Heart_Rate_Calorimetry_Activity_on_Apple_Watch_November_2024.pdf)。因此删除“摄入减活动=盈余/缺口”的表达。
- 每日需求与年龄、身体参数、活动水平有关：[USDA DRI Calculator](https://www.nal.usda.gov/human-nutrition-and-food-safety/dri-calculator)。本项目 D-04 的活动系数已包含日常活动，不把当天记录的运动热量直接回加到可吃额度。
- [NIDDK Body Weight Planner](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)把饮食和活动结合用于计划。现有 7700 kcal/kg 线性换算仅是本项目参考计划，不是动态生理模型或达成保证。本轮只修正同一计划内部的算术矛盾，未声称取得营养专业背书。
- 系统优先是一种保守的去重策略，并非逐条运动的精确对账。现有汇总缺少同一活动的时间区间、来源关联与覆盖范围，不能可靠区分手动新增与重复活动；原始手动记录仍保留。
- 手动运动的 MET/步数公式仍是粗估，可能与设备的净活动能量不同，不用于自动补偿摄入。未擅自替换未有专业背书的 MET 表和步行系数。
- 本轮未新增健康数据权限，也不将系统健康数据持久化或上云。

## 后续值得单独投入的产品改进

1. 营养专业复核 D-04/D-05 与手动运动估值，包括成人模型适用范围、未成年人和特殊人群路径、低体重目标限制。现有通用公式不可当作个体医疗建议。
2. 保存营养目标历史快照，才能对历史记录做当时目标的准确评价。
3. 运动区间和来源映射，用于用户可理解、可撤销的精确去重；当前系统优先可能遗漏设备未采集到的额外手动活动，界面已注明。
4. 采用动态体重模型前需专业评估与数据验证，不能仅以线性热量差宣称能按日达到目标。
