# v1.17.9 产品与设计复核

日期：2026-10-25。基线 v1.17.8（764266b）。采用独立产品、设计和仓储审查，再对发现逐项复现与修复；保持既有五 Tab 和营养规则。

## 本轮解决

1. 首页今日营养卡会继承数据页旧日期。入口现在先选中今天，再进入数据页；普通 Tab 切换仍保留浏览状态。
2. 社区正文测量未跟随系统字号，放大后截断却没有展开。测量与渲染共用 TextScaler；英文连胜徽标允许换行。
3. 食物状态、营养信号徽标和体重目标说明的亮色文字对比不足。保留语义图标/底色，正常文字改用 textPrimary；8 项测试从实际渲染颜色与合成背景检查对比。
4. 拍照/语音批量确认底栏横排拥挤。主按钮独占一行，次操作可换行，支持中英文、亮暗、360×640、2倍字号、300px键盘避让。保存中有忙态，禁背景关闭、下滑和系统返回；部分成功后关闭准确返回成功数量，隐藏会导致重复整餐的重新拍摄入口。
5. 长明细保存失败的错误可能藏在滚动区域外。保留未完成条目并回到错误提示；提供读屏live region。失败不清空已输入份量。
6. 单条记录缺少失败反馈和忙态。现在同一草稿显示行内错误；用户已开始下一条时提示上一条失败，并保留下一条输入。成功收尾只有草稿、搜索和原焦点均未变时才收键盘，保护IME composing。
7. 本地入账后聚合/回读失败会留下已保存记录，重试重复。插入、聚合和回读纳入同一事务，成功后才启动上行与完整撤销窗口。真实SQLite故障注入覆盖回滚、重试、提交前不得上行及在线/离线撤销窗口。
8. 小屏大字体下，待同步提示在键盘展开时让位，额外今日汇总仅在空间充裕时显示，餐次记录仍保留营养信息。

## 验证方法与范围

- 新增测试先确认失败，再修生产逻辑；红灯日志分别记录导航、社区字号、事务、焦点与对比度问题。
- 原生逐页UI交互仍遵循用户“先不检查”指示跳过；Flutter键盘尺寸模拟不等于真机输入法、相机和健康授权验收。
- 本次无服务端或数据库结构改动，无需生产服务端部署。
- 只读审查另发现自然日日期运算跨DST的潜在问题，本轮未复现及修改，留作时区专项；不宣称全项目不存在其他问题。
