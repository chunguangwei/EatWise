# v1.17.10 逻辑修复与发布验收

日期：2026-10-26。版本：`1.17.10+140`。基线：`1e40ce4`。

## 修复范围

- 请求与同步绑定登录会话代际，账号切换后拒绝旧请求、旧响应、令牌刷新和游标写入；同账号重新登录同样隔离。设置、身体资料、断食方案同步保留未完成的 dirty 状态。
- 断食延长的查询、上报和失败入队绑定原账号；换号期间不能向下一账号发请求或写队列。匿名队列迁移先写目标再删来源，避免中断丢失。
- 食物记录首次创建前持久冻结请求，响应丢失后仍用原幂等键对账，再执行用户最新的编辑或删除；重启不重复入账，删除不被下行恢复。匿名记录认领和自定义食物 ID 迁移覆盖在同一流程。
- 删除、撤销、失败回滚与每日营养聚合在同一 SQLite 事务内完成；升级重新核对历史缓存，空日期残留的摄入量可自愈。
- drift 升至 v16，新增可空的创建请求快照；保留现有记录，迁移未确认的旧创建请求。
- 服务端结束断食与同步共用判定，延长周期已完成原目标时正确达标；客户端不能通过同步伪造补签或修改服务端补签结果。
- 断食方案更新按用户串行，并修复历史多个当前方案；食物审核、晋升、纠错和级联删除使用一致的锁与事务，避免并发操作留下半提交状态。
- 日期翻页、趋势、周月统计和缓存修复按自然日计算，覆盖夏令时 23/25 小时日。
