范围：`v1.17.4+134`，覆盖 Flutter 客户端、NestJS 服务端、真实 PostgreSQL、管理台和生产部署。设计参考为用户提供的 7 张华为运动健康截图，保留 EatWise 品牌绿、五 Tab、现有功能和中英文，不引入无数据源的会员、等级或健康指标。

## 主要修复

- **补签与事务**：每月 1 日按用户本地月重置为 2 张，未用完不累积，断档或重新开始不额外送卡。S1、sync、recompute、makeUp 均可懒 rollover。补签窗口为断签日起 `[D, D+6]` 且不含今天，D+7 起拒绝。扣卡、usedDates、补签标记、统计和幂等回执在同一事务提交，异常回滚。Prisma 使用事务内 advisory lock 和 tx-bound driver，memory 同键串行并可回滚。
- **认证与安全**：refresh 原子轮换、同名注册冲突、settingsPrefs 用户锁内键级 merge、密码登录独立限流。帖图和头像请求跳过认证，AuthInterceptor 仅对 API 同源请求注入/刷新。服务端拒绝非法帖图 origin，并在 feed、详情、管理端和旧幂等响应过滤存量非法 URL。管理台修复非空列表渲染和食物名存储型 XSS。
- **账号与同步**：关闭周期墓碑防复活；activeCycle、activePlan、onboarding、streak、feed、userMe 按 uid 和会话代际隔离。下行时间、批响应和游标校验，编辑代际按 clientRequestId + localVersion + deleted 判定。drift v15 同增 Foods.ownerUserId/source 与 water/exercise/fasting.lastError，历史行只在首次登录确定性认领，不清库。
- **日期与偏好**：统一 localDayProvider 处理跨午夜和回前台，weightLogRevisionProvider 刷新体重，settingsPrefs dirty 随 syncNow 重试。方案服务端最后写入胜并即刻 current，本机 pending 仅作旧流程兼容，进行中周期锚点不变。
- **健康与营养**：已授权健康同步冷启动恢复，未授权零平台请求；运动时长、热量和步数统一上限；截图与手动运动共用流程。服务端信号灯按原始值判定，展示才取整，补齐浮点边界 parity。
- **识别与导出**：语音面板返回后不再重复处理，切换在途互斥；拍照成功行移除、累计计数、控制器释放；自定义食物保存成功但入账失败时复用食物，不重复送审。导出包含个人自定义食物和贡献候选，不含 passwordHash；客户端写入 JSON 后调用系统分享。
- **华为参考设计**：240dp 扁平三环和端点图标，核心仪表与双按钮前置；第一图例区分真实断食与进食进度，延长目标包含延长时长。图表改为轻量文字页签和最新非空值大读数，保留零基线/体重 min-max 规则。今日记录按餐次成组卡片，组头真实热量合计，行内编辑删除对齐。我的页使用 64dp 头像、分组标题和线性图标。动作色和彩底前景按对比度选择，普通文字目标 ≥4.5:1。
